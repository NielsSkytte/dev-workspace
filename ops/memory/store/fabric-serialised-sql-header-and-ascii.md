## Whose header it is

Fabric's. Evidence: `Dataverse_Account.sql` was committed by us in `Fabric-ETL` `1a30a30` starting
at `/* ...`; the next commit `dbf4098` ("Committing 2 items from workspace") is Fabric's
commit-from-workspace and is where line 1 `-- Auto Generated (Do not modify) <hash>` appeared.
Microsoft Community Support (thread 4419908, 2025): generated by Fabric's git integration for
internal version control; no API, not reproducible from the file. Simon's generated files carry it
only because they went through the same serialiser. It is a fingerprint, not a lock.

## Three ways to break the file, one error string

All three end in `DmsImportDatabaseException ... Incorrect syntax near '-'`:

1. **LF-terminated header.** Fabric writes line 1 with CRLF; the body is LF. A local edit that
   drops that CR (`aa28638`) passes DacFx, but Fabric's next commit-from-workspace no longer
   recognises its header, prepends a fresh one and leaves `- Auto Generated ...` on line 2
   (`94b9735`, 2026-09-03). Root cause of the 09-03 failures; git itself did not strip the CR
   (`has_crlf_in_index` protects mixed files), the editor did.
2. **Hand-written header on a new file** - same mangling (`0bc4977`, `ed66b3a`, 2026-08-21).
3. **Non-ASCII in a `--` comment** - does not survive the `OBJECT_DEFINITION` round trip; the
   comment ends early and the parser meets a stray `-` (`f1ed16c`). Inside `/* */` or a string
   literal it is harmless (`Date.sql` holds Danish month literals and imports fine).

Correction to the 08-27 version: the `- Auto Generated` line is rejected by **Update from git**
itself (DacFx `SQL46010` on import, 2026-09-03), not only at deployment.

## Enforcement (2026-09-09)

`tools/wh_validate.py`: byte checks (header on line 1 and CRLF, no `- Auto Generated`, ASCII in
`--` comments) and `--build`, a local `dotnet build` of every `*.Warehouse` `.sqlproj` with
`Microsoft.Build.Sql` 2.2.0 - the same engine Fabric runs on import. Verified: injecting the
`94b9735` defect reproduces `SQL46010: Incorrect syntax near '-'` exactly. Unresolved
cross-warehouse references (SQL71501/71561, thousands) are expected offline. One recorded
exception: `CREATE SCHEMA Identity` in Enriched_AX09, written by Fabric itself (`84e0ba1`),
rejected by offline DacFx, accepted by Fabric.

Wired as `core.hooksPath ../tools/githooks` on the `Fabric-ETL` clone: pre-commit = bytes +
`--fix` (repairs an LF header to CRLF), pre-push = `--build`. Bypasses: `--no-verify`, a fresh
clone before the hooksPath command, a commit from the Fabric workspace UI. The repo's `.sqlproj`
pins `0.1.19-preview`, which no longer resolves and which Microsoft lists as a sync-failure cause;
the gate builds a scratch copy with 2.2.0 and leaves the repo alone.
