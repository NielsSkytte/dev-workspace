Building the Matas DataCompare overview deck, two skills fired on purpose and both helped:
`pingala-visual-identity` (palette, Aptos / Aptos Display, and the bundled Fabric + D365 SVG icon
inventory, which is what made the architecture diagram possible at all) and `writing-voice` (no em
dashes, no AI lexicon in the slide prose).

The observation worth keeping is a conflict between them and the store. The visual-identity skill
lists **Ink Free** as the third brand font, "for callout boxes, pull quotes, handwritten-style
annotations, creative highlights". Memory record `feedback-no-agent-names-in-deliverables` records
the owner's instruction never to use handwritten or script fonts (Ink Free named) in formal
technical architecture diagrams. The skill does not carry that exception, so anything reading only
the skill would use Ink Free on exactly the kind of deliverable where the owner has said not to.

Ink Free was not used in the deck. If the skill is edited, the fix is one line in its typography
rules: Ink Free is out of formal technical and architecture deliverables, whatever the element.

Nothing else was missing. No skill fired unhelpfully, and no output had to be corrected that a
skill should have prevented.
