Why: the old CONTEXT.md was append-only ("Completed since last update" stacked per date), so the
Carl Ras card reached 140 KB and a new session read history instead of state; `/handoff` was rarely run
and the "In progress / Next" sections drifted from the task files.

The card (`_templates/CONTEXT.md`): header blockquote with rules of engagement; Goal with a done-when;
Where we stand dated (six lines, one per workstream); Active tasks - progress (GENERATED by
`ops/bin/daybrief.py --write-cards`, never hand-edited); Blocked on others (by name, asks with sent
state); Open threads (max eight, resolved ones leave); Where the detail lives. History goes to
`ops/log/sessions.md` and `CONTEXT_ARCHIVE.md`, decisions to `CONTEXT_DECISIONS.md` (append-only table).

The task file (`ops/tasks/_TEMPLATE.md`): `fno_task` is the DevOps id or the word `none`, never blank;
`customer_ask` none|open|sent DATE|answered mirrors `## Needs from customer`; `waiting_on` / `resume_on`
park a task (fields, not a fifth folder); `## Progress` with `**Now (YYYY-MM-DD):**` (replaced, not
stacked), `**Tried and dropped:**`, `**Next:**` ordered. Progress age = today minus the Now date; stalled
= in progress, not parked, older than 14 days.

Grammar of a generated task line: slug - DevOps id|none. **state.** Now (date): ... Next: ... Customer
ask: .... The card is rewritten, never appended; progress is written when it happens, at the latest at
`/handoff`, and after every compaction (SessionStart `compact` nudge).
